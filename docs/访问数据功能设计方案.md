## 1. 需求与边界

### 1.1 需求描述

在管理后台左侧菜单栏新增「**访问数据**」入口，进入后统计**商城前台网站**的访问情况，页面包含：

| 区域 | 内容 |
|------|------|
| 筛选器 | 快捷日期（近 7 / 30 / 90 天）+ 自定义日期区间 |
| 搜索 | IP / 访问路径 / 关键字 等条件查询 |
| 汇总卡片 | 今日访问、今日访客、区间访问、区间访客、独立 IP 等 |
| 数据趋势 | 按天的 PV / UV 趋势折线图 |
| 流量来源 | 来源渠道占比（下拉/搜索/直接访问/社媒等） |
| 访问明细 | 逐条来源数据记录（时间、IP、归属地、设备、来源、路径、来源页…） |

### 1.2 明确边界（重要）

| 边界 | 说明 |
|------|------|
| ✅ 只统计前台 | 采集只挂在商城前台页面（`app/(store)/**`），后台 `app/admin/**` 不采集 |
| ✅ 排除管理员自身 | 「登录管理后台的管理员」在前台的访问也**不计入**（避免污染数据） |
| ✅ 只统计真实用户 | 默认排除爬虫 / 机器人（bot UA），可选排除内网 IP |
| ❌ 不做全站日志分析 | 不做服务器访问日志（Nginx access.log）级别的采集，只在应用层埋点 |
| ❌ 不改动业务逻辑 | 不改变现有订单 / 支付 / 商品流程，纯增量 |

### 1.3 与参考项目的关系

参考项目 `2Box-master/license-server` 使用 **Express + TypeORM + MySQL + Vue3 + ECharts**；本项目为 **Spring Boot + JPA + PostgreSQL + Next.js + recharts**。

> 因此：**数据模型与统计口径可直接借鉴，但技术实现必须按本项目技术栈重写**（SQL 方言、图表库、UI 组件均不同）。本文档给出的是本项目落地版本。

## 3. 总体设计思路

```
┌──────────────────────────────────────────────────────────────┐
│  商城前台 (app/(store)/**)                                       │
│    VisitTracker (升级)                                          │
│      · 生成/读取 visitor_id (localStorage)                       │
│      · 上报 {path, referer, visitor_id, ...}                     │
│      · 管理员身份 → 不上报                                        │
│      · sendBeacon / fetch keepalive, fire-and-forget             │
└───────────────────────────┬──────────────────────────────────┘
                            │ POST /visit/track  (permitAll)
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  后端 Spring Boot                                                │
│    VisitController.track(body, ip, ua)                          │
│      ├─ UA 解析 (device/os/browser)  UserAgentUtil 扩展          │
│      ├─ IP 归属地解析 (可插拔/可降级/带缓存) IpLocationResolver    │
│      ├─ 来源归类 RefererUtil.classifySource                      │
│      ├─ 写明细 visit_logs                                        │
│      └─ 累加日聚合 visit_stats (PV/UV，保持历史兼容)              │
│                                                                  │
│    AdminVisitController  (需权限 VISIT_VIEW)                     │
│      GET /admin/visit/analytics   汇总+趋势+多维度                │
│      GET /admin/visit/visits      访问明细分页+筛选               │
│      GET /admin/visit/options     筛选下拉选项                    │
│      GET /admin/visit/export      导出 CSV (可选)                 │
└───────────────────────────┬──────────────────────────────────┘
                            │ /api/admin/visit/*  (rewrites 代理)
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  管理后台  app/admin/visit/page.tsx                              │
│    Tab1 流量分析：汇总卡片 + 趋势 + 来源 + 时段 + 设备/OS/浏览器    │
│                   + 地域/运营商 + 热门页面 + 活跃 IP              │
│    Tab2 访问明细：筛选器 + 明细表格 + 分页                         │
│    图表用 recharts，UI 用 shadcn/ui，中英双语 i18n               │
└──────────────────────────────────────────────────────────────┘
```

**三条核心原则：**

1. **采集与展示分离**：埋点只写数据（轻量、fire-and-forget），所有统计计算放在后台查询时做（`GROUP BY` 聚合）。
2. **趋势走日聚合、维度走明细**：区间 PV/UV 趋势与总量读取 `visit_stats`（保证历史连续），来源/设备/地域/路径等维度读取 `visit_logs`（明细维度）。
3. **可降级**：IP 归属地解析、地理信息为**可选增强**，库缺失或解析失败时静默降级为"未知"，不影响主流程。

## 4. 数据采集方案（前台 only）

### 4.1 埋点客户端升级

改造 [visit-tracker.tsx](file:///d:/Projects/orion-key-main/apps/web/components/store/visit-tracker.tsx)：

```tsx
"use client"
import { useEffect } from "react"
import { usePathname } from "next/navigation"
import { useAuth } from "@/lib/context"

const VID_KEY = "nova_vid"

/** 生成/读取访客标识（localStorage 持久化，清除后视为新访客） */
function getVisitorId(): string {
  try {
    let id = localStorage.getItem(VID_KEY)
    if (!id) {
      id = `${Date.now().toString(36)}-${Math.random().toString(36).slice(2, 10)}`
      localStorage.setItem(VID_KEY, id)
    }
    return id
  } catch {
    return "" // 隐私模式等异常时降级为空（后端按 IP 兜底）
  }
}

export function VisitTracker() {
  const pathname = usePathname()
  const { user, authLoaded } = useAuth()

  useEffect(() => {
    // 管理员自身访问前台不计入统计（等待 auth 就绪再判断）
    if (!authLoaded) return
    if (user?.role === "ADMIN") return

    const payload = JSON.stringify({
      path: pathname || "/",
      referer: typeof document !== "undefined" ? document.referrer : "",
      visitor_id: getVisitorId(),
      screen: typeof window !== "undefined" ? `${window.screen.width}x${window.screen.height}` : "",
      lang: typeof navigator !== "undefined" ? navigator.language : "",
    })

    // 优先 sendBeacon（页面卸载也能可靠上报），失败回退 fetch keepalive
    try {
      const ok = navigator.sendBeacon("/api/visit/track", new Blob([payload], { type: "application/json" }))
      if (ok) return
    } catch { /* ignore */ }
    fetch("/api/visit/track", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: payload,
      keepalive: true,
    }).catch(() => { /* fire-and-forget */ })
  }, [pathname, authLoaded, user])

  return null
}
```

**采集时机**：`pathname` 变化（SPA 路由切换）即上报一次，等价于"一次页面浏览（PV）"。首屏加载也会触发一次。

**为什么"不采集后台"是天然成立的**：`VisitTracker` 只挂在 `app/(store)/store-shell.tsx`，而 `app/admin/**` 由独立的 [admin/layout.tsx](file:///d:/Projects/orion-key-main/apps/web/app/admin/layout.tsx) 渲染，不含该组件 → 后台页面根本不会触发埋点。**再加一层**：管理员身份即使访问前台也跳过上报（见上）。

### 4.2 后端上报接口升级

现有 `POST /visit/track` 无 body。升级为接收可选 JSON body（**向后兼容**：老客户端不带 body 时按默认值处理）：

```json
{
  "path": "/product/abc",
  "referer": "https://www.baidu.com/s?wd=xxx",
  "visitor_id": "lr8k2m-9f3a1b",
  "screen": "1920x1080",
  "lang": "zh-CN"
}
```

字段说明：

| 字段 | 必填 | 说明 | 缺省 |
|------|------|------|------|
| `path` | 否 | 前台页面路径 | `/` |
| `referer` | 否 | 来源页（`document.referrer`） | 空 → 判为"直接访问" |
| `visitor_id` | 否 | 前端生成的访客标识 | 空 → UV 去重回退到 IP |
| `screen` | 否 | 屏幕分辨率（供后续分析） | 空 |
| `lang` | 否 | 浏览器语言（供后续分析） | 空 |

服务端补充采集：**客户端 IP**（沿用现有 `extractClientIp`）、**User-Agent**（请求头）。**注意**：不采集后台会话，前端已排除管理员。

### 4.3 反爬 / 反刷（可选，建议默认开启）

- 机器人 UA 过滤：命中 bot 正则（`bot|spider|crawler|slurp|headless|python-requests|curl|wget|axios|okhttp…`）的记录标记为 `device=bot`，默认在汇总中排除、在明细中可筛选。
- 同 IP 高频限制（简单内存计数，比如 1 秒内同 IP > N 次则丢弃）——防止脚本刷量（可作为二期）。
- 内网 / 保留 IP 归为"局域网"，不计入地域 Top。

## 5. 数据库设计

### 5.1 复用：`visit_stats`（日聚合表，保持不变）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID (PK) | 继承 `BaseEntity` |
| visit_date | date (unique) | 统计日 |
| pv | int | 当日 PV |
| uv | int | 当日 UV（IP 去重，历史口径） |
| created_at / updated_at | timestamp | `BaseEntity` |

> **保留不动**：继续写入，承担"趋势与总量"的数据源，保证历史连续。

### 5.2 新增：`visit_logs`（访问明细表）

参照参考项目的 `site_visit_log` 字段，适配本项目 JPA / PostgreSQL：

| 字段 | 类型 | 索引 | 说明 |
|------|------|------|------|
| `id` | UUID (PK) | PK | 继承 `BaseEntity`（与项目其他实体一致） |
| `visit_date` | date | ✅ | 访问日期（用于按天/区间过滤与聚合） |
| `visit_hour` | int | | 访问小时 0-23（时段分布） |
| `ip` | varchar(64) | ✅ | 客户端 IP |
| `country` | varchar(64) | | 国家 |
| `province` | varchar(64) | | 省份 |
| `city` | varchar(64) | | 城市 |
| `isp` | varchar(64) | | 网络运营商 |
| `device` | varchar(16) | | `desktop`/`mobile`/`tablet`/`bot`/`unknown` |
| `os` | varchar(32) | | 操作系统 |
| `browser` | varchar(32) | | 浏览器 |
| `source` | varchar(32) | | 来源渠道（中文标签，默认「其他」） |
| `referer` | varchar(512) | | 来源页完整 URL |
| `path` | varchar(255) | ✅ | 访问路径 |
| `visitor_id` | varchar(64) | ✅ | 访客标识 |
| `user_agent` | varchar(512) | | 原始 UA |
| `screen` | varchar(16) | | 屏幕分辨率（可选） |
| `lang` | varchar(16) | | 浏览器语言（可选） |
| `created_at` | timestamp | ✅ | 访问时间（`BaseEntity` 的 `@CreationTimestamp`） |

**建议复合索引**（PostgreSQL 下按查询模式建）：

- `idx_visit_logs_date_hour (visit_date, visit_hour)` —— 趋势 + 时段分布
- `idx_visit_logs_date_source (visit_date, source)` —— 来源分布
- `idx_visit_logs_date_device (visit_date, device)` —— 设备分布
- `idx_visit_logs_date_path (visit_date, path)` —— 热门页面
- 单列：`ip`、`visitor_id`、`created_at`

> **ID 类型取舍**：本项目 `BaseEntity` 统一 UUID。明细表写入量较大，UUID 索引比 bigint 略大；但为保持项目一致性、避免引入第二套主键规范，**建议沿用 UUID**。若后续数据量极大（千万级），再考虑改 `bigint` + 独立实体。

### 5.3 预留：`visit_session`（会话表，二期可选）

用于"跳出率 / 平均停留时长"等需要会话切分的高级指标（30 分钟无活动切分为一个新会话）。一期可不建，用明细表临时计算近似值。

### 6.3 埋点接口改造

```java
@RestController
@RequestMapping("/visit")
@RequiredArgsConstructor
public class VisitController {

    private final VisitService visitService;

    @PostMapping("/track")
    public ResponseEntity<Void> track(@RequestBody(required = false) TrackRequest body,
                                      HttpServletRequest request) {
        visitService.track(
            body,                                  // 可为 null（老客户端）
            extractClientIp(request),
            request.getHeader("User-Agent")
        );
        return ResponseEntity.noContent().build();
    }
    // extractClientIp 保持不变
}
```

`VisitServiceImpl.track()` 逻辑：

```
1. visitDate/visitHour = 当前时间
2. 解析 UA → device/os/browser     (UserAgentUtil 扩展)
3. 解析 IP  → country/province/city/isp (IpLocationResolver，失败降级空)
4. 归类来源 → source               (RefererUtil.classifySource)
5. 写 VisitLog 明细
6. 累加 visit_stats：pv+1；若当日该 visitorId(IP兜底) 首次 → uv+1
   · 去重判断改为以明细表为准(memory Set 可保留作为快路径优化)
```

> **UV 去重升级**：现有实现用内存 Set 只按 IP。升级后优先按 `visitor_id` 去重（更准），缺失时回退 IP；判断依据落在 `visit_logs` 当日记录是否存在，避免重启丢失基准（内存 Set 可继续作为可选快路径）。

### 6.4 分析服务 `VisitAnalyticsService`

### 6.7 IP 归属地解析（可插拔 + 可降级）

```java
public interface IpLocationResolver {
    IpLocation resolve(String ip);   // 失败返回空对象，绝不抛异常
}
```

- 默认实现 `NoopIpLocationResolver`：返回空归属地（**不引入任何依赖也能跑**）。
- 可选实现 `Ip2RegionLocationResolver`：使用离线库 `org.lionsoul:ip2region`（xdb 文件路径可配置，如 `./data/ip2region.xdb`），**懒加载 + 常驻内存 + 失败降级为空**。
- 结果缓存：`ConcurrentHashMap` + 简易 TTL（同 IP 反复访问不重复查库）。
- 内网 / 保留 IP 归为「局域网」。

> 设计原则：**归属地是增强项，不是必需项**。库缺失 / 加载失败 / 查询异常都必须静默降级，绝不能影响 `track` 主流程。

## 9. 指标口径定义

为避免歧义，统一口径：

| 指标 | 定义 |
|------|------|
| **PV**（页面浏览） | 每次前台页面加载或 SPA 路由切换 +1 |
| **UV**（独立访客） | 同一 `visitor_id` 在同一天内只计 1 次；缺失时按 IP 去重 |
| **独立 IP** | 区间内 `DISTINCT ip` 数量 |
| **新访客** | 该 `visitor_id` 在统计区间**之前**从未出现过 |
| **回访访客** | 该 `visitor_id` 在统计区间之前出现过 |
| **日均访问** | 区间 PV ÷ 区间天数 |
| **时段分布** | 按 `visit_hour` 分组计数 |
| **来源渠道** | 依据 `referer` 域名归类（无 referer → 直接访问） |
| **停留时长 / 跳出率** | 需会话切分（二期） |
| **在线人数** | 近 5 分钟内有访问的去重访客数（二期） |

> 注意：`visit_stats` 的 UV 历史口径为"IP 去重"，升级后 `visit_logs` 为"visitor_id 优先"。**趋势/总量以 `visit_stats` 为准**（保持历史连续），**明细维度以 `visit_logs` 为准**；两处 UV 可能有轻微差异，属预期。

## 10. 保留期、性能与安全

### 10.1 保留期与清理

- 明细保留期默认 **90 天**，可配置（0 = 永久保留）。
- 定时清理：复用操作日志清理的实现模式（Spring `@Scheduled` 或启动时清理），删除 `visit_date < today - retention` 的记录；`visit_stats` 日聚合**永久保留**（体积小）。
- 管理端可提供"立即清理"按钮（可选）。

### 10.2 性能

- 维度聚合全部走 `GROUP BY` + `LIMIT`，配套上文复合索引。
- 明细查询分页用 `Pageable`，排序 `created_at DESC`；大表时 `count(*)` 较慢，可后续改为"估算总数"。
- IP 归属地缓存避免重复查库。
- 埋点写入轻量（单条 insert + 一次 upsert 聚合），必要时异步（`@Async`）—— 一期同步即可。

### 10.3 隐私与安全

- 不采集任何可识别到个人的业务数据（订单号/邮箱等），仅 IP / UA / 路径 / 来源。
- IP 属个人敏感信息，**建议按 90 天保留期清理**；必要时可提供"IP 脱敏"开关（如 `1.2.3.*`）。
- 埋点接口 `permitAll`，但只写不可读；读取接口全部需 `VISIT_VIEW` 权限。

### 10.4 配置项（复用 `site_configs` KV）

| Key | 默认 | 说明 |
|-----|------|------|
| `visit_track_enabled` | true | 埋点总开关 |
| `visit_exclude_admin` | true | 排除管理员的访问 |
| `visit_exclude_bot` | true | 汇总中排除爬虫 |
| `visit_retention_days` | 90 | 明细保留天数 |
| `visit_geolocation_enabled` | false | 是否启用 IP 归属地解析 |
