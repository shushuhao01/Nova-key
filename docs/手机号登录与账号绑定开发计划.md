## 0. 计划说明

### 0.1 阶段划分

| 阶段 | 内容 | 是否可独立上线 | 依赖 |

> **原则**：每个阶段结束时代码可编译、可运行、开关关闭时行为与当前完全一致。

### 0.2 总开关语义（贯穿所有阶段）

```
customer_phone_enabled = false  →  前台不出现任何手机号入口，后端拒绝 phone 参数，行为 100% 等于现状
customer_phone_enabled = true   →  按各子开关分别生效
sms_enabled = false             →  前台不出现任何验证码（短信）入口，后端短信接口返回「短信服务未启用」
```

### 0.4 前台显隐硬性规则（每个阶段都必须遵守）

> 详细矩阵见方案 [§6.8](./手机号登录与账号绑定改造方案.md)。摘要：

| 开关 | 关闭时前台必须消失的内容 |
|---|---|
| `customer_phone_enabled` | 全站所有手机号相关入口（切换器、Tab、绑定按钮、提示条、历史记录） |
| `phone_purchase_enabled` | 商品详情页 / 结算页的「邮箱 / 手机号」切换器（回落到纯邮箱输入） |
| `phone_query_enabled` | 订单查询页的手机号识别、占位符、最近查询里的手机号记录 |
| `phone_login_enabled` | 登录页「手机号登录」Tab 与初始密码提示 |
| `phone_register_enabled` | 注册页「手机号注册」切换 |
| `phone_code_login_enabled` + `sms_enabled` | 登录页「手机验证码登录」Tab |
| `sms_enabled` | 所有短信验证码入口（含个人中心改密短信方式、后台通知模板短信勾选） |
| `anonymous_phone_auto_register` | 支付成功页「已为你创建账号 / 初始密码」卡片（关闭时只创建匿名订单） |

规则：**条件不满足就完全不渲染**（禁止禁用态/灰化/占位）；未启用时不请求相关接口；后端对开关关闭时传来的 `phone` / `phones` 参数一律按「不支持」处理。

### 0.6 结论：可执行性校验

- **依赖闭环**：P0（数据/迁移/Repository）→ P1（开关与白名单）→ P2/P3 可并行 → P4/P5/P6 → P7 → P8，无循环依赖；每阶段结束都可编译、可上线、开关关闭等价于现状。
- **开关闭环**：配置键在「后端 `PUBLIC_KEYS` / `EDITABLE_KEYS` / `DEFAULT` 种子」与「前端 `SiteConfig` 类型 + 显隐矩阵」两侧一一对应，缺一处即可被 §0.4 + §0.5-B4/B5 的验收项拦住。
- **链路闭环**：下单（两个入口）、查单、注册、登录、绑定、合并、通知、优惠券、后台客户/订单/分销/结算均已列出改造点，不存在只改前端的悬空引用。
- **风险闭环**：`sms_enabled` / `customer_phone_enabled` 关闭即回退；数据库只加列，旧版本兼容。
- **剩余不确定项**：C1（手机号注册是否强制短信验证）建议 P1 前确定；不阻塞 P0~P2 编码。

### 任务清单

| # | 任务 | 文件 |
|---|---|---|
| P0-1 | `User` 新增 `phone`、`mustChangePassword`、`phoneRegisteredAt` | `entity/User.java` |

| P0-5 | `NotificationTemplate` 新增 `smsTemplateCode` | `entity/NotificationTemplate.java` |
| P0-6 | 幂等迁移：`users.email DROP NOT NULL`、`users.phone` 唯一部分索引、`orders.phone` 索引 | `config/DataMigrationRunner.java` |
| P0-7 | 历史匿名订单回填脚本（默认关闭） | `config/DataMigrationRunner.java` |

### 关键实现约定

- 索引统一用 `CREATE UNIQUE INDEX IF NOT EXISTS uk_users_phone ON users(phone) WHERE phone IS NOT NULL;`（部分索引，避免多行 NULL 冲突）。
- `orders.phone`：`CREATE INDEX IF NOT EXISTS idx_orders_phone ON orders(phone);`
- `email DROP NOT NULL` 前先查 `information_schema.columns.is_nullable`，已是 `YES` 则跳过。
- 回填脚本由环境变量/配置 `migration.backfill-orders-by-phone=true` 控制，默认 `false`；执行前打印影响行数，单事务提交。
- `contact_type` 允许为空，仅新订单写入，历史订单不强制回填（读取时按 `email != null ? EMAIL : PHONE` 推断）。

### 验收标准

1. 启动应用，`users.phone`、`orders.phone`、`orders.contact_type`、`sms_verification_codes` 表/列自动创建。
2. 重启两次无报错（幂等）。
3. `INSERT` 两条 `phone = NULL` 的用户不冲突；两条相同非空 `phone` 冲突。
4. 历史数据无任何字段被改写（回填开关关闭）。

### 测试用例

| 用例 | 步骤 | 期望 |
|---|---|---|
| T0-1 | 全新库启动 | 所有表/列/索引创建成功 |
| T0-2 | 已有库连续启动 2 次 | 无异常，无重复建索引报错 |
| T0-3 | 手动插入重复 phone | 唯一索引报错 |
| T0-4 | `migration.backfill-orders-by-phone=true` | 打印匹配行数并回填，可回滚到备份 |

### 回滚

- 加列可回滚（`DROP COLUMN`），索引可 `DROP INDEX`；`email DROP NOT NULL` 无需回滚（不影响旧逻辑）。
- 回填脚本执行前必须 `pg_dump` 备份 `orders`。

### 后端校验顺序（必须固定）

```
1. customer_phone_enabled / phone_purchase_enabled 判断
   - 关闭：phone 参数忽略；缺少 email 报「请输入邮箱」
2. 若传 phone：normalize → isValidCnMobile → 否则「手机号格式不正确」
```

### 查询接口规则

- 请求体 `order_ids`、`emails`、`phones` 三者任一非空即可。
- `phone_query_enabled = false` 时收到 `phones` → 忽略并返回提示「手机号查询未启用」，不报 500。
- 结果按 `created_at` 倒序合并去重（key = orderNo）。

### 验收标准

1. 开关开启：仅填手机号可下单成功，订单 `contact_type = PHONE`。
2. 开关开启：邮箱、手机号都不填 → 明确报错。
3. 开关关闭：前台无手机号选项，旧流程完全不变。
4. 订单查询：手机号可查到订单，返回卡密与既有字段一致。
5. 防刷：同 IP 同手机号待支付订单达上限被拦截。

- 前置：`customer_phone_enabled && phone_login_enabled && phone_register_enabled`。

| 密码错误 | 沿用现有「账号或密码错误」+ 失败计数/锁定 |

### 强制改密拦截

- 放行白名单：`/auth/force-change-password`、`/auth/logout`、`/user/profile`、`/user/password`。
- 其他接口返回 403 + `code = MUST_CHANGE_PASSWORD`。
- 改密成功：`passwordVersion + 1`（旧 token 全部失效）、`mustChangePassword = false`、返回新 token。

### 找回密码规则

| 账号形态 | 行为 |

### 验收标准

1. 手机号注册成功即登录，直接进入个人中心，无需再登录。
2. 已注册手机号再次注册 → 「该手机号已注册，请直接登录」。

5. 手机号账号未绑邮箱点击忘记密码 → 明确提示先绑定邮箱。
6. 管理员账号用手机号登录 → 被拒绝并提示。

### 阿里云调用实现要点

- Endpoint：`https://dysmsapi.aliyuncs.com/`
- 公共参数：`Action=SendSms`、`Version=2017-05-25`、`Format=JSON`、`RegionId`、`AccessKeyId`、`SignatureMethod=HMAC-SHA1`、`SignatureVersion=1.0`、`SignatureNonce=UUID`、`Timestamp=UTC ISO8601`
- 业务参数：`PhoneNumbers`、`SignName`、`TemplateCode`、`TemplateParam`（JSON 字符串）
- 签名：`GET&%2F&` + `URLEncoder(按 key 升序拼接的 k=v&...)`，key = `secret + "&"`，Base64(HMAC-SHA1)
- 错误码映射：`isv.BUSINESS_LIMIT_CONTROL`（触发流控）、`isv.MOBILE_NUMBER_ILLEGAL`（手机号非法）、`isv.AMOUNT_NOT_ENOUGH`（余额不足）、`SignatureDoesNotMatch`（AK/SK 错误）、`isv.SMS_SIGNATURE_ILLEGAL`（签名不合法）、`isv.TEMPLATE_MISSING_PARAMETERS`（模板参数缺失）
- 未配置/未启用：直接返回失败「短信服务未启用」或「短信服务未配置」，**禁止伪造成功**

### 验证码频控

| 项 | 值来源 |
|---|---|
| 发送间隔 | `phone_code_interval_seconds`（60s） |
| 单号每日上限 | `phone_code_daily_limit`（10） |
| 有效期 | `phone_code_expire_minutes`（10） |
| 错误次数 | 5 次作废（常量） |
| 一次性消费 | `used = true` |

### 通知渠道联动

- `notification_channels` 插入 `SMS` 行（幂等），`configJson = {"phone_to": ""}`。
- 模板勾选 SMS 时必须填 `sms_template_code`，否则保存报错。
- `sms_enabled = false` → 后台 SMS 渠道开关禁用 + 前台无验证码入口。
- 发送条件：`sms_enabled && channel.enabled && template.smsTemplateCode != null && phone_to 非空`。

### 验收标准

1. 未配置短信时：后台「短信配置」可打开但保存启用会提示先填 AK/SK/签名/模板；前台无任何验证码入口。
2. 配置正确后「测试连通」成功返回；AK/SK 错误返回明确错误码文案。
3. 「测试发送」能收到短信；失败展示阿里云真实错误码。
4. `sms_enabled = true` 后登录页出现「手机验证码」，未启用则不出现（不显示禁用态）。
5. 消息通知勾选短信、未填模板 CODE → 保存失败并提示。
6. 通知发送：SMS 渠道按配置成功发送；未配置时跳过并记录日志，不阻塞其他渠道。

|---|---|
| T6-1 错误 AK/SK 测试连通 | `SignatureDoesNotMatch` 友好提示 |
