## 2. 核心机制设计

### 2.1 客户绑定与保护期机制

```
客户通过推广链接进入网站
  → 记录推广员ID到 Cookie（30天有效）
  → 客户下单（注册用户 or 匿名邮箱）

下单时检查：
  1. 查 customer_binding 表，看该客户（userId 或 email）是否已绑定推广员
  2. 如果已绑定且在保护期内 → 归属原推广员
  3. 如果已绑定但保护期已过 → 检查 Cookie 中的推广员
     a. Cookie 有新推广员 → 更新绑定到新推广员
     b. Cookie 无推广员 → 保持原绑定（或解绑）
  4. 如果未绑定 → 用 Cookie 中的推广员创建绑定
  5. 如果 Cookie 也无推广员 → 不产生佣金
```

**匿名用户绑定继承**：
```
匿名用户用邮箱下单 → 绑定推广员到邮箱
  → 用户后来注册（同邮箱）
  → 自动将邮箱绑定迁移到 userId
  → 历史绑定关系保留
```

### 2.2 阶梯佣金机制

同一客户（同一 userId 或同一 email）在同一推广员下的多次购买，佣金比例按阶梯递减。

**配置示例**：

| 购买次序 | 佣金比例（占默认佣金比例的百分比） |
|---------|-------------------------------|
| 第 1 次 | 100%（即全额佣金比例） |
| 第 2 次 | 60% |
| 第 3 次 | 30% |
| 第 4 次起 | 0%（不返佣） |

**计算示例**：
```
默认佣金比例：10%
商品价格：¥100

第1次购买：佣金 = 100 × 10% × 100% = ¥10
第2次购买：佣金 = 100 × 10% × 60% = ¥6
第3次购买：佣金 = 100 × 10% × 30% = ¥3
第4次购买：佣金 = 0
```

**阶梯规则配置**：后台可配置每一级的比例和最大次数。也可设置为"不限次数"模式（所有次数都是100%）。

### 2.3 二级分销机制

```
一级分销员 A 邀请用户 B 成为分销员
  → B 成为 A 的下级（parent_distributor_id = A.id）
  → B 推广商品，客户购买
  → B 获得佣金（如 ¥10）
  → A 从 B 的佣金中抽成（如 30% = ¥3）
  → B 实得 ¥7，A 实得 ¥3

层级限制：最多 2 级
  → A → B（2级，允许）
  → A → B → C（3级，不允许，B 不能邀请下级）
```

**抽成比例配置**：
- 全局配置一级从二级抽成的默认比例
- 可为每个一级分销员单独配置抽成比例

### 2.4 佣金比例优先级

```
1. 分销员 × 商品 自定义比例（最高优先级）
2. 商品 自定义比例
3. 分销员 自定义默认比例
4. 全局默认比例（最低优先级）
```

计算时取最终比例，再乘以阶梯系数。

### 2.5 佣金计算公式

```
佣金金额 = 订单项金额 × 佣金比例 × 阶梯系数

一级抽成 = 下级佣金金额 × 一级抽成比例
下级实得 = 下级佣金金额 - 一级抽成
```

### 2.6 全店推广机制

分销员可生成「全店推广链接」（不绑定特定商品）。客户通过全店推广链接进入后：

```
客户通过全店推广链接进入
  → 设置 Cookie: dist_ref={distributor_id}
  → 客户浏览任意商品并下单
  → 下单时检查 Cookie 中的推广员
  → 如果购买的商品参与分销 → 产生佣金
  → 如果购买的商品被排除（is_excluded=true）→ 不产生佣金
  → 客户绑定到该推广员（保护期机制同样适用）
```

**全店推广 vs 商品推广**：

| 类型 | 链接格式 | 绑定商品 | 跳转目标 |
|------|---------|---------|---------|
| 商品推广 | `/p/{linkCode}` | 是 | 直接跳转商品详情页 |
| 全店推广 | `/p/{linkCode}` | 否（product_id=null） | 跳转首页 |

两种链接都设置同一个 Cookie（`dist_ref`），下单时追踪逻辑一致。

### 2.7 佣金计算时机与有效性保障

**核心原则：只有真正付款的订单才算有效，未付款的订单不产生任何佣金。**

```
订单状态流转与佣金关系：

PENDING（待支付）
  → ❌ 不产生佣金记录
  → ❌ 不更新推广链接的 order_count
  → 如果超时未支付 → 订单作废，无任何影响

PAID（已支付）
  → ✅ 创建佣金记录（status=PENDING，待结算）
  → ✅ 更新推广链接的 order_count
  → ✅ 更新客户绑定的 purchase_count（用于阶梯佣金）
  → ✅ 记录 purchase_tier（第几次购买）

DELIVERED（已发货）
  → 佣金保持 PENDING 状态
  → 发货后 24 小时无其他操作 → 自动流转为 COMPLETED（定时任务，每5分钟）

COMPLETED（已完成）
  → ✅ 订单自动完成（deliveredAt + 24h）或手动完成
  → ✅ 记录 completed_at
  → 佣金结算条件：订单 COMPLETED 且 completedAt < 当前时间 - settle_delay_days
    （即"订单完成 + N 天"后佣金才入可提现余额，防止退款套佣）

EXPIRED（已过期/未支付）
  → ❌ 不产生佣金
  → ❌ 不更新任何统计

REFUNDED（全额退款）/ PARTIALLY_REFUNDED（部分退款）
  → 管理后台对已支付/已发货/已完成订单发起微信支付退款（原路退回）
  → 退款金额 ≤ 订单实付金额（可多次部分退款，累计不可超过实付金额）
  → 退款时佣金记录 status=CANCELLED
  → 如果佣金已结算（SETTLED）→ 从 available_balance 扣回
  → 如果佣金已提现 → 标记为待追回，从后续佣金中扣除
```

**防亏钱校验链**：

```
1. 佣金创建时（PAID）：
   → commission_amount = order_amount × base_rate × tier_rate / 100
   → 一切基于实际付款金额（actualAmount），不含优惠券抵扣

2. 佣金结算时（SETTLED）：
   → available_balance += self_commission（仅本人实得部分）
   → parent 的 available_balance += parent_commission（上级抽成部分）

3. 提现申请时：
   → 检查 available_balance >= 申请金额
   → available_balance -= 金额
   → frozen_balance += 金额

4. 提现成功时：
   → frozen_balance -= 金额
   → withdrawn_amount += 金额

5. 提现失败/拒绝时：
   → frozen_balance -= 金额
   → available_balance += 金额（退回）

6. 佣金取消时（退款）：
   → 如果 status=PENDING → 直接 CANCELLED
   → 如果 status=SETTLED → available_balance -= commission（可能变负数 → 标记待追回）
```

### 2.8 推广数据统计指标

| 指标 | 说明 | 计算方式 |
|------|------|---------|
| 点击量 | 推广链接/二维码被点击的次数 | promotion_link.click_count |
| 独立访客 | 不同IP的点击数 | distribution_click 去重统计 |
| 下单量 | 通过推广链接提交订单的数量 | order_count（含未付款） |
| 付款量 | 实际付款的订单数 | commission_record 中该链接关联的记录数 |
| 转化率(点击→下单) | 下单量 / 点击量 × 100% | order_count / click_count |
| 转化率(下单→付款) | 付款量 / 下单量 × 100% | paid_count / order_count |
| 转化率(点击→付款) | 付款量 / 点击量 × 100% | paid_count / click_count |
| 销售额 | 付款订单的总金额 | SUM(order_amount) |
| 佣金总额 | 产生的佣金总和 | SUM(commission_amount) |

## 3. 数据库设计

### 3.1 新增表（9 张表）

#### 3.1.1 `distributor`（分销员表）

```sql
CREATE TABLE distributor (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID NOT NULL REFERENCES users(id),
    distributor_code VARCHAR(20) NOT NULL UNIQUE,   -- 推广员ID，如 D2026081
    parent_distributor_id UUID REFERENCES distributor(id), -- 上级分销员（二级分销用）
    status          VARCHAR(20) NOT NULL DEFAULT 'PENDING', -- PENDING/APPROVED/REJECTED/DISABLED
    custom_rate     DECIMAL(5,4),                    -- 自定义默认佣金比例
    sub_rate        DECIMAL(5,4) DEFAULT 0.30,       -- 从下级佣金抽成比例（一级分销员用）
    level           INT NOT NULL DEFAULT 1,           -- 1=一级, 2=二级
    
    -- 微信绑定
    wechat_openid      VARCHAR(64),
    wechat_unionid     VARCHAR(64),
    wechat_nickname    VARCHAR(64),
    wechat_bound_at    TIMESTAMP,
    
    -- 余额
    total_commission    DECIMAL(12,2) DEFAULT 0,     -- 累计佣金
    available_balance   DECIMAL(12,2) DEFAULT 0,     -- 可提现余额
    frozen_balance      DECIMAL(12,2) DEFAULT 0,     -- 冻结中（提现申请中）
    withdrawn_amount    DECIMAL(12,2) DEFAULT 0,     -- 已提现总额
    
    -- 统计
    total_sales         DECIMAL(12,2) DEFAULT 0,     -- 累计销售额
    total_orders        INT DEFAULT 0,               -- 累计订单数
    
    created_at   TIMESTAMP NOT NULL DEFAULT NOW(),
    approved_at  TIMESTAMP,
    disabled_at  TIMESTAMP,
    
    UNIQUE(user_id)
);
```

#### 3.1.2 `distribution_rule`（分销规则配置表，单行）

```sql
CREATE TABLE distribution_rule (
    id                    INT PRIMARY KEY DEFAULT 1,
    is_enabled            BOOLEAN NOT NULL DEFAULT false,   -- 总开关
    default_rate          DECIMAL(5,4) NOT NULL DEFAULT 0.10, -- 默认佣金比例 10%
    auto_approve          BOOLEAN NOT NULL DEFAULT false,   -- 自动审核分销员
    min_withdraw_amount   DECIMAL(12,2) NOT NULL DEFAULT 10.00, -- 最低提现金额
    max_withdraw_amount   DECIMAL(12,2) NOT NULL DEFAULT 20000.00, -- 单笔最高提现
    settle_delay_days     INT NOT NULL DEFAULT 7,           -- 结算延迟天数
    withdraw_fee_rate     DECIMAL(5,4) NOT NULL DEFAULT 0,  -- 提现手续费率
    protection_days       INT NOT NULL DEFAULT 30,          -- 客户保护期（天）
    cookie_days           INT NOT NULL DEFAULT 30,          -- 推广Cookie有效天数
    enable_secondary      BOOLEAN NOT NULL DEFAULT true,    -- 是否开启二级分销
    default_sub_rate      DECIMAL(5,4) NOT NULL DEFAULT 0.30, -- 一级从二级抽成默认比例
    enable_tier_commission BOOLEAN NOT NULL DEFAULT false,  -- 是否开启阶梯佣金
    max_commission_count  INT NOT NULL DEFAULT 0,           -- 阶梯佣金最大次数（0=不限）
    created_at            TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at            TIMESTAMP NOT NULL DEFAULT NOW(),
    
    CONSTRAINT single_row CHECK (id = 1)
);
```

#### 3.1.3 `commission_tier`（阶梯佣金配置表）

```sql
CREATE TABLE commission_tier (
    id              INT PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
    rule_id         INT NOT NULL DEFAULT 1 REFERENCES distribution_rule(id),
    tier_order      INT NOT NULL,              -- 第几单（1, 2, 3...）
    rate_percentage DECIMAL(5,2) NOT NULL,     -- 占基础佣金比例的百分比（100=全额, 60=六成）
    created_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    
    UNIQUE(rule_id, tier_order)
);
```

#### 3.1.4 `product_commission`（商品佣金配置表）

```sql
CREATE TABLE product_commission (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    product_id      UUID NOT NULL REFERENCES products(id),
    custom_rate     DECIMAL(5,4),              -- 自定义佣金比例（null 用全局默认）
    is_excluded     BOOLEAN NOT NULL DEFAULT false, -- 是否排除（不参与分销）
    created_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    
    UNIQUE(product_id)
);
```

#### 3.1.5 `distributor_product_rate`（分销员×商品 自定义比例）

```sql
CREATE TABLE distributor_product_rate (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    distributor_id  UUID NOT NULL REFERENCES distributor(id),
    product_id      UUID NOT NULL REFERENCES products(id),
    custom_rate     DECIMAL(5,4) NOT NULL,     -- 自定义佣金比例
    created_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    
    UNIQUE(distributor_id, product_id)
);
```

#### 3.1.6 `customer_binding`（客户绑定表）

```sql
CREATE TABLE customer_binding (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    distributor_id  UUID NOT NULL REFERENCES distributor(id),
    user_id         UUID REFERENCES users(id), -- 绑定的用户（注册用户）
    email           VARCHAR(255),              -- 绑定的邮箱（匿名用户）
    bind_type       VARCHAR(20) NOT NULL,      -- USER / EMAIL
    purchase_count  INT NOT NULL DEFAULT 0,    -- 该客户在此推广员下的购买次数
    bound_at        TIMESTAMP NOT NULL DEFAULT NOW(), -- 绑定时间
    expires_at      TIMESTAMP NOT NULL,        -- 保护期到期时间
    last_order_at   TIMESTAMP,                 -- 最后一次下单时间
    
    -- 同一用户/邮箱同一时间只能绑定一个推广员
    UNIQUE(user_id),
    UNIQUE(email)
);
```

#### 3.1.7 `promotion_link`（推广链接表）

```sql
CREATE TABLE promotion_link (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    distributor_id  UUID NOT NULL REFERENCES distributor(id),
    product_id      UUID REFERENCES products(id), -- null = 全店推广
    link_code       VARCHAR(16) NOT NULL UNIQUE,  -- 短链码
    link_type       VARCHAR(20) NOT NULL DEFAULT 'PRODUCT', -- PRODUCT / STORE
    click_count     INT NOT NULL DEFAULT 0,       -- 点击量
    unique_click_count INT NOT NULL DEFAULT 0,    -- 独立访客数（去重IP）
    order_count     INT NOT NULL DEFAULT 0,       -- 下单量（含未付款）
    paid_count      INT NOT NULL DEFAULT 0,       -- 付款量（实际付款）

      "commission_preview": 10.00,
      "commission_rate": 0.10,

    },
    {
      "product_id": "uuid2",
      "is_excluded": true,
      "has_distribution": false,
      "commission_preview": 0,
      "commission_rate": 0,
      "max_commission": 0,
      "max_commission_rate": 0
    }
  ]

```

**显示逻辑**：

| 用户状态 | 显示内容 | 佣金计算 |
|---------|---------|---------|
| 未登录 | `💰 分享赚 ¥15.00`（max_commission） | 取全局所有商品中配置的**最高佣金比例**计算 |
| 已登录非分销员 | `💰 分享赚 ¥15.00`（max_commission） | 同上，引导申请成为分销员 |
| 已登录分销员（无自定义比例） | `💰 分享赚 ¥10.00`（commission_preview） | 用分销员默认比例（=商品比例 or 全局默认） |
| 已登录分销员（有自定义比例） | `💰 分享赚 ¥12.00` | 用分销员自定义比例 |
| 商品被排除 | 不显示标签 | is_excluded=true |

**max_commission 计算规则**：
```
max_commission_rate = MAX(
  全局默认佣金比例(default_rate),
  该商品自定义比例(product_commission.custom_rate),
  所有分销员自定义比例中的最大值(MAX(distributor.custom_rate))
)

max_commission = product_price × max_commission_rate × 100%（阶梯第一档）
```

> 取最高比例显示，让未登录/非分销员用户看到最有吸引力的佣金金额。登录成为分销员后，显示其实际能赚的金额。

## 8. 微信转账到零钱流程

### 8.1 前提条件

| 项目 | 说明 |
|------|------|
| 微信公众号（服务号） | 用于获取用户 openid 和 JSAPI |
| 公众号 AppID + AppSecret | 网页授权获取 openid |
| 微信支付商户号 | 已开通「商家转账到零钱」 |
| 商户 API 证书 | .pem 格式，放在服务器上 |
| 商户 API V3 密钥 | 用于签名和验签 |
| 安全 IP 配置 | 服务器公网 IP 加入白名单 |
| 网页授权域名 | 在公众号后台配置 noepay.cn |

### 8.2 绑定微信流程

```
1. 分销员点击"绑定微信"
2. 后端生成公众号网页授权 URL：
   https://open.weixin.qq.com/connect/oauth2/authorize?
     appid=APPID&
     redirect_uri=https://noepay.cn/my/distribution/bind-wechat/callback&
     response_type=code&
     scope=snsapi_base&
     state={distributor_id}#wechat_redirect
3. 用户在微信内打开链接，微信授权
4. 微信回调带 code 参数
5. 后端用 code 换 access_token，获取 openid
6. 存储 openid 到 distributor 表
7. 绑定成功
```

> **注意**：绑定微信必须在**微信内**完成（需要微信授权）。非微信浏览器提示用户用微信扫码进入。

## 9. 定时任务与兜底机制

| 任务 | 频率 | 说明 |
|------|------|------|
| 订单自动完成 | 每 5 分钟 | 已发货（DELIVERED）超过 24 小时的订单自动置为已完成（COMPLETED） |
| 佣金结算 | 每小时 | 扫描 PENDING 状态佣金记录，所属订单已完成（COMPLETED）且超过 settle_delay_days 的标记为 SETTLED |
| 提现状态查询 | 每 5 分钟 | 扫描 PROCESSING 状态的提现记录，调用微信查询 API 兜底 |
| 提现超时处理 | 每 30 分钟 | 超过 24 小时未确认收款的提现，调用撤销 API 并退回余额 |
| 客户绑定过期 | 每天 | 扫描过期的客户绑定，标记为过期状态 |
| 推广数据统计 | 每天 | 更新 promotion_link 的 paid_count/total_sales/total_commission |
| **余额对账** | 每天 | 核对每个分销员的余额一致性，不一致则报警日志 |
| **未付款订单清理** | 每小时 | 检查 PENDING 超时订单，标记为 EXPIRED（不产生佣金） |

## 10. 安全与风控

### 10.1 数据隔离

- **前台用户**：所有 API 从 JWT 中提取 userId，反查 distributor，**只能查看自己的数据**
- **后端校验**：每个查询都带 `distributor_id = ?` 条件，防止越权
- **管理后台**：管理员可查看全部数据，但操作有日志记录

### 10.2 资金安全（防亏钱保障）

**核心原则：佣金基于实际付款金额计算，未付款不产生佣金，退款必扣回佣金。**

| 风控项 | 措施 | 说明 |
|--------|------|------|
| **仅付款订单产生佣金** | 佣金在订单 PAID 时创建 | PENDING/EXPIRED 状态不产生任何佣金 |
| **佣金基于实际付款金额** | 用 actualAmount 计算 | 不含优惠券抵扣、积分抵扣部分 |
| **自购不返佣** | 下单时检查推广员ID ≠ 购买用户ID | 防止分销员自己买赚自己佣金 |
| **佣金冻结期** | 订单完成（COMPLETED）后 N 天才结算 | 已发货 24h 自动完成，订单完成 + N 天才可提现，防止退款套佣 |
| **退款必扣回佣金** | 佣金记录 CANCELLED | 已结算的从余额扣回，已提现的标记待追回 |
| **提现审核** | 所有提现需管理员手动审核 | 双重保障 |
| **提现冻结** | 申请时冻结余额 | available→frozen，防止超额提现 |
| **转账幂等** | 用 out_bill_no 保证唯一 | 防止重复转账 |
| **转账兜底** | 定时查询 PROCESSING 状态 | 防止回调丢失 |
| **超时撤销** | 24 小时未确认收款自动撤销 | 退回冻结余额 |
| **金额校验** | 单笔最低 ¥1，最高 ¥20000 | 微信限制 |
| **余额校验** | 提现前检查 available_balance >= 金额 | 数据库行锁防并发 |
| **余额对账** | 定时核对余额一致性 | SUM(commission) = available + frozen + withdrawn |

**余额一致性对账公式**：

```
对每个分销员：
  理论可提现 = SUM(self_commission WHERE status=SETTLED) - SUM(withdrawal WHERE status=SUCCESS)
  
  实际可提现 = distributor.available_balance
  
  如果 理论可提现 ≠ 实际可提现 → 报警，人工排查

理论已提现 = SUM(withdrawal WHERE status=SUCCESS)
实际已提现 = distributor.withdrawn_amount
  如果不等 → 报警

理论冻结 = SUM(withdrawal WHERE status IN (PENDING, APPROVED, PROCESSING))
实际冻结 = distributor.frozen_balance
  如果不等 → 报警
```

**并发安全**：

```
提现申请使用数据库行锁（SELECT FOR UPDATE）：
  1. SELECT * FROM distributor WHERE id = ? FOR UPDATE
  2. 检查 available_balance >= 申请金额
  3. available_balance -= 金额
  4. frozen_balance += 金额
  5. UPDATE distributor SET ...
  6. INSERT withdrawal_record ...

佣金入账使用数据库行锁：
  1. SELECT * FROM distributor WHERE id = ? FOR UPDATE
  2. available_balance += self_commission
  3. UPDATE distributor SET ...
```

### 10.3 防刷机制

| 风控项 | 措施 |
|--------|------|
| 推广链接刷点击 | 同一 IP 24 小时内只计 1 次点击 |
| 虚假订单佣金 | 佣金在订单发货后创建，退款时取消 |
| 恶意绑定 | 保护期机制防止客户被反复抢夺 |
| 分销员刷单 | 管理员可查看异常数据并禁用 |

## 10A. 消息通知系统（前台铃铛 + 邮件同步）

### 10A.1 设计概述

在现有管理后台通知系统基础上，**新增前台用户消息中心**，每个用户有自己的铃铛消息。所有业务事件按用户维度投递消息，避免串户。

```java
@Async
@Override
public void sendUserMessage(UUID userId, String email, String code, Map<String, Object> vars) {
    // 1. 查模板
    NotificationTemplate t = templateRepository.findByCode(code).orElse(null);
    if (t == null || !t.isEnabled()) return;

    // 2. 渲染
    Map<String, Object> merged = new LinkedHashMap<>(vars);
    merged.putIfAbsent("site_name", siteName());
    merged.putIfAbsent("time", now());
    String title = render(t.getTitle(), merged);
    String content = render(t.getContent(), merged);

    // 3. 写入 user_message（指定 userId，防串户）
    UserMessage msg = new UserMessage();
    msg.setUserId(userId);         // 注册用户
    msg.setEmail(email);           // 匿名用户邮箱
    msg.setTemplateCode(code);
    msg.setCategory(t.getCategory());
    msg.setTitle(title);
    msg.setContent(content);
    msg.setMetadata(writeJson(vars));  // 附加数据用于跳转
    messageRepository.save(msg);

    // 4. 邮件同步（仅当管理后台启用邮箱发件 且 用户有邮箱时）
    if (emailEnabled() && email != null && !email.isBlank()) {
        try {
            emailService.sendNoticeEmail(email, "【" + siteName() + "】" + title, content);
        } catch (Exception e) {
            log.warn("User message email sync failed: {}", e.getMessage());
        }
    }
}
```
